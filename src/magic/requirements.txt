Perform the same procedure as the Magic Puzzle mode in the normal crosshatch app, with the following modifications:
1. Don't give any explanations of what is happening, just show the grid with the seed word in the slot where it's currently being considered.
2. All letters should be shown in white, no colored backgrounds or font colors based on any buckets.
3. After 10 fills have been found, stop the fill process, choose the one with the highest fill score, and display it in the grid.

Below this show the text "Generating..." while the puzzle is generating.
When the generation is done, show 2 buttons with the text above them "How does this look?"

- Try Again causes the the generation to continue for 10 more fills and them asks again.

Any items that are crossed out will not be used in any of the fills that are subsequently generated for the current puzzle (doesn't persist to other puzzles).
Cancel, to the left of Try Again, and an x both close the modal without marking anything Don't Use. Try Again applies the crossed-out answers and generates again.

CLUES PANEL
The clues panel should generally take after the Clues View in the main app, with some additional requirements.

As soon as the clue panel is opened, query any existing AI generated clues from the generated_clue table that have is_seedword = false. 
Also query their clue type information. For any entries that have less than 7 existing clues, submit an AI prompt to clue_prompt.txt 
 to generate more. Submit up to 10 entries per prompt, one prompt at a time, using grok-4.6 (via chal-api's makeAICall). Retry each prompt up to 2 times; apply each batch's clues as soon as it returns. This will be done in the background, and while 
 the response is pending, show a spinner icon next to all the entries for which AI results are loading.

As soon as the clue panel is opened, also query any existing community clues from the community_clue table. 
No prompt needs to be sent if there aren't any.

For entries that have AI generated clues, automatically select a clue to populate for it. 1/3 of the time, the auto-selected clue should be
 the Straight clue type. 1/3 of the time it should be Association (if that type exists for the entry). The rest of the time, pick a random
 other clue type that exists for that entry.

When a clue is clicked, instead of opening an edit textbox directly, open a modal.
1. The modal will have an edit textbox at the top with an OK button to submit and close the modal. Pressing enter does the same thing as the OK button.
2. Underneath the modal will be 2 lists of suggested clues. Clicking on any selected clue sets the clue to that clue and also closes the modal.
3. The first list is a list of AI generated clues for the given entry, those queried earlier. If there is a pending AI prompt, as soon as 
    the results are returned, update the list with the new clues.
4. The second list is a list of community clues for the given entry, also queried earlier.

At the bottom of the Clues Panel is a button Finish Puzzle that is enabled as soon as all entries have clues.
To the left of the Finish Puzzle button should be 2 checkboxes:
- "Contribute my clues to community clues" (checked by default). If checked, on clicking Finish Puzzle, any clues other than the seed answer 
    clue that do not exactly match the text of an existing AI generated clue or and existing community clue will be added to the community_clue table.
- "Including my seed answer clue" (unchecked by default). If checked, the seed answer clue will also be added to the community_clue table if 
    different from any existing clue.

Finally, on pressing Finish Puzzle, a magic_puzzle record will be created for the puzzle. Additionally, a clue_collection will be created and 
 clue records will be created and tied to the collection. This is similar to how it's done in the cruzi-scraper project except the 
 clue_collection will tie to the magic_puzzle instead of the puzzle record.
